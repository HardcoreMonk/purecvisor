# 서비스 기능 영상 소개 설계

> 상태: Verified — 공개 영상 소개 범위
> 요청: 기존 네트워크 기능 테스트 영상을 공개 landing의 직관적이고 미려한 기능 소개로 사용한다.

## 설계와 도메인 경계

기존 브랜드와 Astro/Starlight 문서 구조를 시각 목표로 삼는다. hero 다음에 기능 선택,
대표 영상, 관련 장면과 네트워크 문서 링크를 배치한다. Local VPC·OVN SDN·VXLAN의
3개 기능과 6개 주요 장면을 보여 준다. 문서 맵·검색·기존 주소는 유지한다.

`ServiceShowcase.astro`가 정적 의미 구조를, `service-videos.mjs`가 공개 영상·언어별
설명을, `service-showcase.js`가 선택·재생 상태를 소유한다. 상태는 페이지 수명에 한정한다.
제품 API·계정·daemon과 연결하지 않는다. 기존 Single Edge 경계와 문서 route가 유효하며
새 제품 도메인이나 backend ADR은 필요하지 않다.

## 디자인 검토

Tailscale의 제품 중심 구성, Arcade의 큰 미디어와 선택 패턴, SST의 기술 콘텐츠 frame을
참고하되 기존 흰 배경·Pretendard·청록색 역할을 유지한다. Replo·Make의 기능 탭과
명시적인 play를 참고한다. 별도 장식 이미지·자동 재생·새 디자인 시스템은 도입하지 않는다.

## Plan Grilling

영상 전체를 처음에 다운로드할 이유는 없다. 포스터만 표시하고 사용자 play 때 소스를
연결한다. 다른 기능을 선택하면 기존 재생을 멈추고 새 포스터를 보여 준다. 자동 다음
영상은 없다. 실패 시 재시도·직접 영상 링크로 복구한다. 무음 영상에는 장면별 요약을
함께 제공한다. 시험 화면을 현재 모든 환경의 기능 인증이나 클러스터 관리로 설명하지 않는다.

원본 로그·관리 endpoint·계정 표시를 공개 asset에 복제하지 않는다. 공개용 crop·구간
편집은 촬영 사실을 바꾸지 않으며 별도 manifest에 길이·hash·편집 범위를 기록한다.

## Spec Freeze Snapshot

사용자 요청 범위는 공개 landing의 영상 소개 구현과 게시다. 기존 디자인·문서 구조를
보존하는 직접 구현으로 진행한다. 3개 기능·6개 MP4, 1개 플레이어, 실제 포스터,
ko/en copy, 지연 로드, 접근 가능한 키보드·모바일·dark 상태가 완료 기준이다.
제품 runtime 변경은 없다. 미디어 실패와 과도한 초기 다운로드를 반사실로 검증한다.


## 운영 검증

3개 기능·6개 공개 MP4·지연 로드·키보드·모바일·dark·오류 복구를 localhost와 실제
도메인에서 확인했다. 공개 구현 `7633ba434a957813b1d374984c787173ccb18887`의
[운영 인계](../../operations/2026-09-08-service-video-showcase-handoff.md)가 게시·복구·
검증 제한의 정본이다. 이 판정은 영상 소개 UI 범위이며 제품 전체 기능 인증은 아니다.
