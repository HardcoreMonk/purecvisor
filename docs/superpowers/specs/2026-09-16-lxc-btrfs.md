# 선택형 LXC Btrfs 저장소 설계

- 상태: Approved (사용자의 다음 단계 구현 승인, 2026-09-16)
- 범위: Single Edge 컨테이너 저장소. VM 저장소·클러스터·자동 마이그레이션은 포함하지 않는다.
- 근거: [조사](../../research/2026-09-16-lxc-btrfs-backend.md), [native 실기](../../operations/2026-09-16-lxc-btrfs-live-validation.md), [ADR-0058](../../adr/0058-lxc-storage-backend-identity.md).

## Intake와 도메인 설계

기존 컨테이너 생성·복제·스냅샷·삭제가 ZFS 명령과 현재 기본 pool 이름에 결합돼 있다. Btrfs 호스트에서 명시적으로 backend를 선택하고 실제 컨테이너의 저장소 식별자를 기준으로 후속 작업을 수행한다.

`[container] storage_backend=zfs|btrfs`를 추가하며 기본값은 `zfs`다. 잘못된 값은 오류다. Btrfs 선택 시 `lxc_path`가 실제 Btrfs이고 관리자가 소유한 경로인지 확인한다. 배포판 이름에 따른 자동 선택, dir fallback과 ZFS fallback은 없다. 새 컨테이너의 backend 선택과 기존 컨테이너의 backend 조회를 분리한다.

컨테이너 설정 디렉터리의 `purecvisor.storage`에 버전, backend, ZFS 실제 dataset 또는 Btrfs filesystem UUID와 rootfs subvolume UUID/ID를 저장한다. 파일은 rootfs 밖에 둔다. 기존 marker 없는 ZFS는 실제 mountpoint와 dataset을 대조해서 호환한다. marker 없는 native Btrfs는 자동 편입하지 않는다. 경로 이탈·symlink·잘못된 marker·다른 filesystem/subvolume으로 바뀐 rootfs는 mutation 전에 거부한다.

## 동작 계약

1. 생성은 Btrfs 사전 검사를 통과한 뒤 `lxc-create -B btrfs`를 사용하고 실제 identity를 영속화한다. 기존 ZFS 생성 경로를 명시적 분기로 보존한다.
2. Btrfs 복제는 정지 상태의 원본에서 native CoW clone을 사용한다. 대상은 새 저장소 identity, 원본 image metadata와 요청자의 owner를 갖는다. 원본 owner를 복사하지 않는다.
3. Btrfs 스냅샷은 rootfs의 읽기 전용 snapshot이다. 이름은 기존 검증 규칙을 따른다. nested subvolume과 별도 mount를 포함한 원본은 누락을 숨기지 않고 거부한다.
4. Btrfs snapshot 생성·복제·복원은 정지 상태에서만 허용한다. 컨테이너 작업 lock을 함께 사용한다.
5. 복원은 rootfs만 교체한다. 현재 LXC config, owner, image metadata를 보존한다. sibling rootfs와 복원 후보를 `renameat2(RENAME_EXCHANGE)`로 교환하고 durable journal로 중단 지점을 복구한다. 일반 rename 두 번으로 원자성을 주장하지 않는다.
6. journal에는 이전/후보 UUID를 기록한다. 실제 rootfs와 staging identity로 교환 전·후를 구분한다. 모호한 상태는 데이터를 보존하며 오류로 남긴다. 다음 mutation/start 전에 recovery를 실행한다.
7. 삭제는 저장된 filesystem/subvolume identity와 관리 snapshot의 경계를 먼저 검증한다. Btrfs 경로에 기존 ZFS용 광범위 `nftw` fallback을 적용하지 않는다. 중첩 subvolume 또는 외부 mount가 있으면 삭제 전에 거부한다. 부분 삭제는 영속 상태를 남겨 재시도할 수 있게 한다.
8. 생성 실패 정리는 이번 작업이 만든 대상만 대상으로 한다. 중복 대상 생성 실패가 기존 데이터를 삭제해서는 안 된다.
9. API의 accepted 응답과 실제 완료 결과를 구분하며 기존 owner/RBAC, worker audit와 WS 결과 계약을 유지한다.

## Grill-me 검토

- 기본값 변경 시 기존 데이터에 잘못된 명령이 실행되는가? marker의 실제 backend가 우선하며 legacy ZFS는 실제 mountpoint로 확인한다.
- native snapshot restore를 그대로 사용할 수 있는가? 실기에서 owner/meta 소실을 확인했으므로 rootfs 전용 복원으로 제한한다.
- snapshot이 모든 디스크 데이터를 포함하는가? nested subvolume과 외부 mount는 제외될 수 있으므로 최초 지원에서는 거부한다.
- 삭제/복원 중 실패하면 무엇이 남는가? identity와 journal을 근거로 복구하며 불명확한 대상은 자동 삭제하지 않는다.
- rootless·quota·운영 안정성도 인증하는가? 이번 완료 기준은 root가 관리하는 privileged LXC의 기능 검증이다. rootless Btrfs 생성은 검증 전 명시 거부한다. 디스크 quota, 송수신 백업, 장시간 안정성은 별도다.

## 비시각 흐름 검토

제품 화면의 구조와 스타일은 변경하지 않는다. 설정·오류·문서에서 backend, 정지 필요, snapshot 범위와 재시도 상태를 일관되게 표시한다. Refero 시각 리뷰 대상이 아니다.

## 수용 기준

- 새 모듈의 실제 production 코드를 실행하는 회귀: 잘못된 선택값, 비Btrfs 경로, 경로 이탈, marker 변조, 중복 생성, nested subvolume, mount, snapshot 중복, 복원 중단 상태, 삭제 실패와 재시도.
- 기존 ZFS argv 분기와 owner/audit/비동기 계약 회귀 유지.
- 공개 소스 build/test/check-all/release 및 주석 정책 통과.
- 승인된 Arch 시험 호스트에서 실제 PureCVisor API로 생성, 부팅, 정지/재시작, CoW 복제, snapshot 생성/목록/복원/삭제, owner/meta 보존, 음성 테스트와 정리 검증.
- 실제 바이너리·설정·호스트 상태의 전후 증거, 남은 제약과 복구 절차를 운영 인계에 기록한다. Native LXC 테스트만으로 제품 완료를 선언하지 않는다.
