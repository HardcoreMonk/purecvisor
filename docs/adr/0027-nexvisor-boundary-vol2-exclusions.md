# ADR-0027: NexVisor 경계 — vol2 항목의 purecvisor 2.0 명시 제외

날짜: 2026-07-08
상태: accepted

## 맥락
초기 확장 설계에는 차세대 트랙(NexVisor) 지향 항목이 다수 포함되어 있었다.
2026-07-08 범위 검토에서 이들을 PureCVisor 2.0 로드맵에서 제외하고 ADR로
경계를 고정했다. 이 결정을 별도 ADR로 유지하지 않으면 향후 기획에서 같은
항목이 다시 유입되는 스코프 드리프트 위험이 있다.

## 결정
다음 항목은 **purecvisor 2.0에서 구현하지 않고 NexVisor 트랙으로 이관**한다:
- AF_XDP 자체 데이터플레인
- VPP 플러거블 데이터플레인 (ADR-NET-006)
- P4 정책 언어 (ADR-NET-007)
- SRv6 라우팅 plane (ADR-NET-009)
- kTLS 컨트롤플레인 (ADR-NET-014)
- io_uring 통합 이벤트 루프의 전면 확대 (ADR-NET-010 — purecvisor는
  UDS 경로 기적용으로 충분)

purecvisor 2.0의 eBPF 방향은 D07 스펙(관측·LSM 감사 인프라)이 정의하며,
패킷 처리 경로 변경(XDP 방화벽 등)은 성능 근거 확보 후 별도 에픽으로만
연다.

## 결과
- 좋음: vol2 원문 재독 시 스코프 재협상 차단, 2.0 에너지를 Tier 1
  도메인(D07·D09·D10·D13)에 집중.
- 나쁨: NexVisor 착수 시 이 목록의 재평가 필요 — 그 시점의 커널·생태계
  기준으로 재설계한다(본 ADR은 2.0 경계만 규정).

## 하지 않기로 한 것
- 항목별 개별 ADR을 만들지 않는다 — 경계 결정 하나로 묶는다.
- NexVisor 트랙 자체의 설계를 여기서 하지 않는다.
